# v0.2: реализация и тестовые контракты

Основание — список v0.2 в [ТЗ](../mvp-spec.md). Возможности реализованы после
зафиксированного RED-прогона. Все 113 тестов Vitest и 6 сценариев Playwright
проходят, включая регрессии MVP и границы интеграции. Без skip/todo/test.fails.

```sh
pnpm test:v02

pnpm typecheck
pnpm lint
```

## Уточнения контрактов

Исходная документация перечисляет возможности, но не задаёт все сигнатуры и
жесты. Следующие решения зафиксированы тестами и реализованы в v0.2.

### Сетка

Сохраняется `generateFrames(width, height, frameWidth, frameHeight)`. Добавляется
необязательный пятый параметр `{ offsetX, offsetY, gapX, gapY }`; отсутствие
параметра эквивалентно четырём нулям. Публичный API — entities/sprite/domain.

Все четыре значения — конечные неотрицательные целые числа. Неверные значения
вызывают ошибку утилиты, UI показывает валидацию. Пустое поле не приравнивается
к нулю до завершения ввода. За пределами доступной полной ячейки получается
пустая сетка и ошибка UI; отрицательное количество кадров недопустимо.

```text
x = offsetX + column × (frameWidth + gapX)
y = offsetY + row × (frameHeight + gapY)
columns = max(0, floor((imageWidth - offsetX + gapX) / (frameWidth + gapX)))
rows    = max(0, floor((imageHeight - offsetY + gapY) / (frameHeight + gapY)))
```

Последнему кадру не нужен промежуток после него. ID идут по строкам с нуля.
Неполные края и клики по полям/промежуткам игнорируются. Изменение любого
Offset/Gap сбрасывает выбор и preview. Поля имеют доступные имена `Offset X`,
`Offset Y`, `Gap X`, `Gap Y`.

### Массовый выбор

`Select All` выбирает только полные кадры, повторное нажатие не добавляет дубли.
`Clear Selection` снимает выделение и очищает preview. Нет изображения/валидной
сетки — Select All недоступен; нет выбора — Clear Selection и экспорт недоступны.
Поведение activeFrame при Select All намеренно не фиксируется.

### Zoom и Pan

Кнопки: `Zoom in`, `Zoom out`, `Reset view`. Zoom изменяет отображаемый размер,
а не исходные размеры canvas, сетку, выбор или crop. Reset возвращает исходный
вид текущего изображения, сохраняя выбранные ID.

Область просмотра имеет роль region и имя `Sprite viewport`. Pan выполняется
перетаскиванием средней кнопкой мыши; оно не выбирает кадры. Клик после Pan/Zoom
учитывает преобразование координат. Шаг и пределы масштаба не навязываются тестами.
Реальную геометрию layout проверяет Playwright; jsdom этого не доказывает.

### ZIP

Публичный контракт feature export-sprites:

```ts
exportFramesZip(image: HTMLImageElement, frames: readonly SpriteFrameGeometry[]): Promise<Blob>
```

Утилита получает уже отобранные кадры, кодирует PNG через реальную логику
нарезки и возвращает Blob `application/zip`. Она не скачивает архив и не создаёт
object URL. Пустой список и ошибка кодирования отклоняют Promise. При ошибке
не возвращается частичный архив. Исходный массив не сортируется на месте.

Архив содержит только переданные кадры в порядке ID. Имена прежние:
ID 0 → frame_001.png, ID 4 → frame_005.png. Нет дополнительных JSON/папок.
Кнопка `Export ZIP` скачивает один архив `<имя без расширения>_sprites.zip`.
Обычный `Export selected` сохраняется. URL ZIP освобождается после скачивания.
На время кодирования источник, сетка и массовый выбор блокируются, затем
становятся доступны и при успехе, и при ошибке.

## Фикстуры и независимость проверок

`src/test/fixtures/spaced.png`: 114×78, кадр 32×32, offset 10/8, gap 4/6.
Ожидаются шесть кадров с началами `(10,8)`, `(46,8)`, `(82,8)`, `(10,46)`,
`(46,46)`, `(82,46)`. Фон полей яркий, содержимое ячеек различается,
первый пиксель ячейки прозрачен. Геометрические ожидания записаны явно.

`src/test/v02/readZip.ts` — только тестовый читатель обычного ZIP, поддерживает
STORE/DEFLATE и проверяет CRC и размеры. Он не используется приложением.
Его три проверки используют независимые архивы Python zipfile, включая
повреждение содержимого. ZIP64, шифрование и многотомные архивы не требуются.

Vitest использует прежние моки Browser API. PNG в этих моках — условные байты;
ZIP-тест проверяет точное сохранение разных байтов кадров в настоящем архиве.
Перед проверкой rejection загружается реальный exportFramesZip: отсутствие
функции не может случайно засчитаться как успешная проверка обработки ошибки.

Playwright открывает настоящее приложение, проверяет Zoom/Pan на test.png
и ZIP на spaced.png. Архив распаковывается независимо, каждый PNG декодируется
в браузере, весь RGBA-массив сравнивается с исходной областью. Так проверяются
целая ячейка, отсутствие полей/сетки в результате и сохранение прозрачности.
Автоматическое определение целого персонажа не входит в v0.2.

Рекомендуемый порядок реализации: Offset/Gap → выбор → Zoom/Pan → массовые
действия → ZIP. После каждого этапа запускать новые тесты и baseline MVP.
Forge2D Save-flow, анимации, автоматическое распознавание и backend не входят в этап.

## Результат реализации

Все 113 Vitest и 6 Playwright проходят. TypeScript, Oxlint и production-сборка
проверяются отдельно. Существующие проверки не удалялись и не ослаблялись.

Zoom: 25–800% от исходного вписанного вида, шаг ×1.25; Reset view сбрасывает
масштаб и перемещение, не выбор. Замена изображения сбрасывает вид.
Pan — средняя кнопка мыши; область просмотра обрезает выходящие за её границы
части изображения. Координаты экспорта всегда относятся к исходным пикселям.

ZIP создаётся fflate в режиме STORE: PNG уже сжат, повторное сжатие не требуется.
Скачивание выполняется отдельно через downloadBlob, domain не зависит от fflate.
Save-flow Forge2D, распознавание персонажей и анимации остаются вне реализации.
