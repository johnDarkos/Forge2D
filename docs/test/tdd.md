# MVP: TDD-контракты и история RED → GREEN

Запуск, устройство моков, сопровождение и диагностика: [руководство по тестированию](testing.md).

Исходное ТЗ сохранено в `docs/mvp-spec.md`. Базовые 48 тестов были написаны
до реализации. Сейчас MVP реализован; набор расширен до 52 тестов Vitest и
4 браузерных сценариев Playwright. Обычный `pnpm test:run` должен проходить.
Не использовать `skip`, `todo`, `test.fails` или подмену бизнес-логики ради GREEN.

## Запуск

```sh
pnpm test:run
pnpm exec vitest run src/test/mvp/browser.test.ts
pnpm typecheck
pnpm lint
```

Первый прогон: 48 тестов, 3 PASS (инфраструктура), 45 FAIL (отсутствует MVP).
Все 45 ошибок — `MVP not implemented: ...`, а не сбои загрузки зависимостей.

## Контракты реализации

ТЗ не фиксирует все сигнатуры и детали интерфейса. Для исполняемых тестов приняты
следующие решения; это уточнения тестового контракта, а не дополнительные функции:

- `src/entities/sprite/lib/generateFrames.ts` экспортирует именованную `generateFrames(imageWidth, imageHeight, frameWidth, frameHeight)`.
  Возвращает массив `SpriteFrame` из ТЗ в порядке строк, ID с 0; неверные размеры
  кадра вызывают исключение, слишком большой кадр даёт пустой массив.
- `src/features/export-sprites/lib/exportFrame.ts` экспортирует именованную асинхронную
  `exportFrame(image, frame): Promise<Blob>`. Утилита нарезает и кодирует PNG;
  управление скачиваниями и URL находится в вызывающем коде. Ошибки Canvas и
  `toBlob(null)` отклоняют Promise, UI показывает понятное сообщение.
- `src/app/App.tsx` — default export компонента приложения. При реализации его
  подключён к `src/main.tsx`; Playwright проверяет страницу через эту точку входа.
- File input имеет доступное имя `Upload image` или `Upload sprite sheet`;
  поля — `Frame width`, `Frame height`; canvas — `Sprite sheet`, preview —
  `Frame preview`; кнопка — `Export selected`. Ошибки имеют `role="alert"`.
- Счётчики подписаны `Columns: N`, `Rows: N`, `Frames: N`, `Selected frames: N`
  (допускается `Selected: N`). Обновление сетки происходит при изменении полей.
- Последний выбранный кадр становится активным для preview. Смена сетки или
  изображения очищает выбор и preview. Preview может удаляться или очищаться.
- Имя PNG связано с исходным ID: ID 0 → `frame_001.png`, ID 10 → `frame_011.png`.
  Выбранные кадры скачиваются в порядке исходных ID, даже при пропусках.
- Масштаб CSS не меняет координаты кадра. Клик по незавершённому краю не выбирает кадр.

`contracts.ts` лениво загружает настоящие модули через `import.meta.glob`.
Отсутствующий модуль даёт отдельную явную ошибку в каждом тесте, при этом TypeScript
можно проверять уже на RED-этапе. Бизнес-логика и React-компоненты не замоканы.

## Моки и пределы проверки

`browser.ts` заменяет только Browser API: Image, Canvas 2D/toBlob, object URL,
скачивание через anchor. Файлы для jsdom содержат условные байты: декодирование
заменено асинхронным load/error с размерами из мок-данных. `toBlob` возвращает
фиктивный Blob, который НЕ является настоящим PNG. Тесты проверяют исходную
область, размеры, MIME и передачу Blob, но не работу PNG-кодека браузера.
`fetch` и XMLHttpRequest запрещены моками; это проверка обычных путей отправки,
а не доказательство отсутствия всех возможных сетевых каналов.

Для реальной проверки в браузере добавлены валидные PNG `player.png` (256×128),
`uneven.png` (100×100), `enemy.png` (64×32) в `src/test/fixtures`. В них кадры
различаются цветом, а первый пиксель каждой ячейки прозрачен. Независимый эталон
координат и RGBA содержится в `pixel-oracle.json`.

Playwright (`pnpm test:e2e`) проверяет в настоящем браузере: пройти upload →
select → export с этими PNG, декодировать скачанный PNG и сравнить его размеры,
цвета и альфа-канал с эталоном. Также проверяются несколько скачиваний, отсутствие горизонтального переполнения
при 1024px и выбор кадра на изображении 4096×4096. Визуальное качество проверяется
по скриншотам; браузерный тест не является benchmark.
Тест генерации 16384 кадров не является измерением производительности UI.
